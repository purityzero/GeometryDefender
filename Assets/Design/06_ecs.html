06 · ECS Hybrid

ECS Hybrid 아키텍처

본 프로젝트의 기술적 차별점은 ECS(DOTS/Job/Burst)와 MonoBehaviour를 혼용하는 Hybrid 아키텍처다. 적 시뮬레이션처럼 데이터 병렬화가 명확한 영역만 ECS로 처리하고, 나머지는 OOP로 유지한다. 모든 곳에 ECS를 적용하는 것은 오버킬이며, 본 문서는 그 경계선을 명확히 정의한다.

왜 Hybrid인가

Unity ECS는 강력하지만 학습 곡선이 가파르고, OOP에 익숙한 시스템 (UI, 카드, 매니저류)을 ECS로 옮기면 복잡도가 폭증한다. 도구는 문제에 맞게 골라 쓴다는 원칙으로 영역별 분리.

영역아키텍처이유
적 시뮬레이션ECS500+ 동시 인스턴스, 단순 직선 이동, SoA 친화
투사체ECS50+ 동시 인스턴스, 적과 충돌 판정 SIMD 처리
중앙 타워MonoBehaviour인스턴스 1개. ECS 이점 없음.
카드 시스템MonoBehaviourUI 중심, 사용자 입력 처리, 참조 타입 데이터
UI / HUDMonoBehaviourUGUI는 본질적으로 MonoBehaviour
메타 진행MonoBehaviour저장/로드, 트리 그래프 순회
웨이브 매니저MonoBehaviour시간 기반 트리거. ECS 적 생성 호출
면접 어필 포인트

"ECS를 모든 곳에 쓰지 않고, 성능 임팩트가 명확한 영역에만 선택적으로 적용. RPG / 콘텐츠 도메인에서 ECS 학습 후, 그 복잡도가 과한 경우를 직접 경험. 본 프로젝트는 그 경험을 바탕으로 한 의식적 도구 선택의 결과."

ECS 컴포넌트 명세

모든 ECS 컴포넌트는 IComponentData 또는 IBufferElementData.

ECS 시스템 명세

각 시스템은 단일 책임. ISystem 권장 (Burst 지원).

핵심 시스템: CollisionSystem

가장 부담이 큰 시스템. Naive O(N×M) 비교 대신 Spatial Hash Grid로 적과 투사체를 영역별 분류 후, 동일/인접 셀끼리만 비교.

통신 비용

MonoBehaviour → ECS 호출은 비용이 작지 않다. 매 프레임 수십 회 호출은 피하고, 이벤트 기반으로 호출 (적 스폰 시점, 발사 시점에만). 매 프레임 호출되는 쿼리(타겟 탐색)는 가능한 한 ECS 측에 묶는다.

적 시각화: 어떻게 그릴까

ECS Entity는 GameObject가 아니므로 SpriteRenderer를 직접 가질 수 없다. 두 가지 옵션:

옵션 A — Entities Graphics

Unity Entities Graphics 패키지. MaterialMeshInfo로 ECS 측에서 직접 렌더링. 진정한 DOTS 풀스택. 학습 비용 큼.

옵션 B — Hybrid Visual

ECS는 데이터만, 렌더링은 MonoBehaviour 풀에서 처리. ECS 위치 → 활성 SpriteRenderer로 동기화. 구현 단순.

MVP 선택: 옵션 A (Entities Graphics).

이유: ① 옵션 B는 결국 GameObject 인스턴스 500개를 풀에서 돌려쓰는 것이고, ECS의 절반 가치가 사라진다. ② Entities Graphics는 RenderMeshInstanced 기반이라 드로우콜 효율 극대화. ③ 면접 시 "ECS 풀스택 경험" 어필 강력.
