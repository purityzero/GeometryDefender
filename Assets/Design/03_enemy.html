03 · Enemy

적 시스템

적은 화면 가장자리에서 스폰되어 중앙 타워를 향해 직선 이동한다. AI는 의도적으로 단순화되어 있다 — ECS Job 내에서 Burst 컴파일 가능한 데이터 구조를 유지하기 위함이다. 다양성은 행동이 아닌 도형 × 컬러 × 스탯으로 확보한다.

적 분류 체계

적은 두 축으로 분류된다. 기본 종(Species)은 도형과 스탯 원형을 결정하고, 변종(Variant)은 시간 경과에 따른 강화 단계다.

SPECIES — 5종

Normal / Swift / Heavy / Splitter / Ranged. 각 도형으로 1차 식별. 모두 적색 베이스.

VARIANT — 3단계

Normal → Elite → Boss. 엘리트는 마젠타 컬러, 보스는 별 도형 + 골드.

변종(Variant)

변종은 기본 종 위에 덧붙는 강화 레이어다. 시간 경과에 따라 출현 확률이 증가하며, 변종마다 별도 스폰 테이블이 있는 것이 아니라 기본 종의 스폰에 변종 확률이 곱해지는 구조다.

스폰 시스템

스폰 위치

적은 카메라 뷰포트 바깥쪽 반경 7.0 unit 원 둘레에서 무작위 각도로 스폰. 화면에서 약간 떨어진 위치에서 페이드 인. 

spawnAngle = Random(0, 360°)
spawnPos = (cos(angle) * 7.0, sin(angle) * 7.0)

스폰 페이스

스폰 페이스는 시간 함수로 계산. 후반부 곡선이 가팔라진다.

spawnRate(t) = baseRate * (1 + t / 60) ^ 1.3
  baseRate = 1.0 (초당 1체)
  t        = 경과 시간 (초)

t=0    → 1.0 체/초   (분당 60)
t=60   → 2.46 체/초  (분당 148)
t=300  → 17.0 체/초  (분당 1020)
t=600  → 49.0 체/초  (분당 2940)

행동 패턴

ECS Job 호환을 위해 행동은 4가지 상태로만 정의된다. BehaviorTree 대신 단순 enum 상태머신을 사용한다. 

enum EnemyState : byte {
    Spawning  = 0,   // 화면 밖에서 페이드 인 (0.3초)
    Moving    = 1,   // 중앙 향해 직선 이동
    Attacking = 2,   // Ranged 전용 (정지 + 발사)
    Dying     = 3,   // 사망 페이드 아웃 (0.2초) + XP 드랍
}

모든 적은 Spawning → Moving → Dying 경로를 따른다. Ranged만 Moving → Attacking 전이가 추가된다.

왜 BT가 아닌가

BT는 디자이너 친화적 시각 도구지만, ECS Job 내에서 사용할 수 없다 (참조 타입 / 가변 트리 구조). 본 프로젝트는 적 수 폭증 대응이 1순위 목표이므로 ECS 호환 단순 enum 상태머신을 선택. BT는 v2 PC 빌드에서 검토.

적 ECS 데이터 구조

각 적은 다음 컴포넌트들의 조합으로 표현된다.

// 모든 적이 가지는 필수 컴포넌트
EnemyTag           : (마커)
LocalTransform     : float3 position, rotation, scale
EnemyStats         : float maxHp, currentHp, moveSpeed, towerDamage
EnemyVisual        : float4 tint, int spriteIndex
EnemyState         : byte (enum)

// 종(Species)별 추가 컴포넌트
SplitterComponent  : int childCount, int childEnemyId   (Splitter 전용)
RangedComponent    : float fireCooldown, float fireRange (Ranged 전용)
EliteTag / BossTag : (마커)

종별 동작 차이는 컴포넌트 유무로 시스템이 분기 처리. Polymorphism을 enum + 추가 컴포넌트 패턴으로 풀어냈다.
